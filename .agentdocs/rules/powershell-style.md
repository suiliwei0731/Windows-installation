# PowerShell 脚本编码标准

适用于资源根目录 `06_Scripts` 下的全部脚本。修改脚本前必须遵守。

## 一、文件与命名

- 脚本使用动宾式短横线命名，动词在前、宾语在后（如 `Check-System.ps1`、`Install-Runtimes.ps1`）。
- 每个脚本职责单一，单个文件不超过 500 行，超限则拆分功能。
- 统一使用 UTF-8 with BOM 保存，避免中文乱码。

## 二、文件头

每个脚本首部包含 `#Requires`（如需管理员权限）与注释块，注释块至少说明：用途、参数、示例调用。

```powershell
#Requires -Version 5.1
<#
.SYNOPSIS
  检查系统版本、架构、权限与磁盘空间。
.DESCRIPTION
  ...
.EXAMPLE
  .\Check-System.ps1 -Root "D:\InstallKit"
#>
```

## 三、参数与执行模式

- 使用 `[CmdletBinding()]` 与 `param()` 块，参数命名用 PascalCase。
- 所有脚本必须提供 `-Root` 参数用于指定资源根目录，并在缺省时按根目录识别约定自动定位。
- 所有会修改系统的脚本必须提供 `-DryRun` 开关，且默认按 `settings.json` 的 `dry_run_default` 决定是否模拟执行。
- 模拟执行时只输出将要执行的动作与命令，不产生实际系统变更。

## 四、日志与错误处理

- 统一通过 `07_Logs` 下的日期日志文件记录，格式为 `操作 | 对象 | 结果 | 退出码 | 时间`。
- 使用 `begin/process/end` 三段式或函数内 `try/catch/finally`，捕获异常并写入日志。
- 依赖前置步骤的操作，前置失败时必须停止执行后续步骤并保留日志。
- 不得擅自强制重启系统；如需重启，仅输出提示并等待用户确认。
- 检查外部程序结果时，必须判断退出码，不得仅凭是否有输出判断成败。

## 五、安全与可重复执行

- 不写死盘符，不写死机器相关路径；路径统一由根目录拼接。
- 不关闭 Windows Defender、UAC 或驱动签名验证。
- 不静默修改浏览器首页、默认搜索引擎或系统安全设置。
- 脚本应可重复执行：执行前检查是否已满足条件，对已完成的步骤合理跳过。
- 对高风险操作（存储驱动覆盖、分区/引导相关），必须先提示并要求用户二次确认。

## 六、输出与交互

- 使用中文输出提示信息，专业名词可保留英文并在首次出现时附中文注释。
- 交互式确认使用 `Read-Host` 或统一入口脚本的确认环节；不得静默执行风险操作。
- 面向用户的最终结果应可通过 `09_Reports` 中的报告追溯。
