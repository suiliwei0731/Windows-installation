# Windows 11 纯净装机环境架构说明

## 一、项目目标

搭建一套可重复使用的 Windows 装机资源库，用于系统重装后的驱动安装、运行库部署、基础软件安装及环境初始化。

要求：

1. 安装包集中存储在独立的装机硬盘中，不依赖系统盘。
2. 优先使用微软、硬件厂商及软件项目的官方安装包。
3. 优先保证网卡驱动可用，确保重装后能够联网。
4. 将 DirectX、Visual C++、.NET Runtime 等常用运行库提前准备好。
5. 显卡、声卡、芯片组等驱动优先通过 Windows Update 或厂商官方渠道获取。
6. 支持手动安装，也支持通过脚本按顺序执行安装。
7. 具备清晰的目录结构、安装日志、失败提示和重复执行保护。
8. 不使用来源不明的万能驱动包、DLL 合集、破解软件或未经验证的系统精简工具。

## 二、整体架构

采用分层结构：

- 资源层：存储 ISO、驱动、运行库和软件安装包。
- 配置层：记录软件名称、版本、架构、下载地址、安装参数及校验值。
- 执行层：通过 PowerShell 脚本完成环境检查、安装和更新。
- 日志层：记录安装结果、失败原因和执行时间。
- 更新层：检查官方新版本，下载至暂存目录，验证后再归档。

执行流程：

检查系统 → 检查网络 → 安装网卡驱动（如需要）→ 更新 Windows → 安装芯片组和硬件驱动 → 安装运行库 → 安装基础工具 → 生成安装报告。

## 四、软件及驱动资源清单

### 1. 网络驱动

优先级最高。

需要准备：
- 有线网卡驱动。
- 无线网卡驱动。
- 蓝牙驱动（按实际硬件决定）。

要求：
- 优先从电脑品牌官网、主板官网或网卡厂商官网获取。
- 记录适用型号、硬件 ID、Windows 版本、CPU 架构和驱动版本。
- 如果驱动为 INF 格式，允许使用 Windows 自带的 PnPUtil 安装。
- 安装前检查驱动签名和适用设备。
- 不得盲目安装所有网卡驱动。

如果暂时无法确定硬件型号，应先建立驱动目录和清单，不得随意下载所谓的万能驱动。

### 2. 芯片组及硬件驱动

包含：
- 芯片组驱动。
- 显卡驱动。
- 声卡驱动。
- 存储控制器驱动。
- 触控板、蓝牙及其他专用设备驱动。

显卡和其他硬件驱动优先通过 Windows Update 或硬件厂商官网获取。只有在明确硬件型号后，才下载对应的离线驱动包。

不得通过强制覆盖驱动的方式追求版本更新。存储控制器和启动关键驱动必须特别谨慎，避免导致系统无法启动。

### 3. Visual C++ Runtime

官方来源：

https://learn.microsoft.com/zh-cn/cpp/windows/latest-supported-vc-redist

准备：
- 最新受支持的 x64 安装包。
- 最新受支持的 x86 安装包。

要求：
- 兼容已安装的同系列运行库，不要先卸载旧版。
- 优先使用官方支持的静默安装参数。
- 检查进程退出码，并记录安装结果。
- 不要从第三方 DLL 网站单独下载缺失文件。

### 4. DirectX Runtime

官方来源：

https://www.microsoft.com/en-us/download/details.aspx?id=35

用途：
- 为部分旧游戏及旧软件补齐传统 DirectX 辅助组件。

注意：
- Windows 已自带 DirectX 系统组件。
- 旧版运行库用于补充旧组件，不应替换系统 DirectX。
- 仅在确有需要时安装，不要重复执行无意义的安装。

### 5. .NET Runtime

官方来源：

https://dotnet.microsoft.com/zh-cn/download/dotnet

要求：
- 根据实际软件需求选择 .NET Desktop Runtime 或其他对应运行时。
- 区分 .NET Framework 与现代 .NET。
- 不要默认安装所有版本。
- 不要将运行时与 SDK 混为一谈；普通桌面软件一般不需要 SDK。

### 6. 常用工具

建议准备：
- 7-Zip 官方安装包。
- 浏览器官方安装包。
- Windows Terminal（按需）。
- 系统信息、磁盘和网络诊断工具。
- PowerShell 环境检查脚本。

所有工具均应记录官方下载页面、版本、架构、文件大小及 SHA-256 校验值（官方提供或本地计算）。

## 五、配置文件设计

software-manifest.json 用于管理资源，建议每个条目至少包含：

- id：唯一标识。
- name：软件名称。
- category：驱动、运行库或工具。
- version：版本号。
- architecture：x64、x86、Arm64 或 Any。
- official_url：官方下载地址或官方发布页面。
- local_path：本地安装包路径。
- installer_type：EXE、MSI、MSU、INF 或 ZIP。
- silent_args：经官方文档确认的静默安装参数。
- sha256：文件校验值。
- requires_admin：是否需要管理员权限。
- install_order：建议安装顺序。
- optional：是否可选安装。
- status：待下载、已验证、已安装或失败。

敏感配置不得保存密码、激活密钥或其他凭据。清单中的下载地址和参数必须经过验证，不得由脚本猜测。

## 六、自动化脚本要求

### Check-System.ps1

检查：
- Windows 版本和构建号。
- 系统架构。
- 管理员权限。
- 可用磁盘空间。
- 当前资源库路径。
- 是否存在必要安装包。

### Check-Network.ps1

检查：
- 有线网卡、无线网卡是否正常识别。
- IP 地址和 DNS 状态。
- 是否能够访问官方 HTTPS 网站。
- 当前是否具备网络下载条件。

没有网络时，应输出明确提示，并引导使用本地离线驱动。

### Install-Runtimes.ps1

按配置清单安装 Visual C++、必要的 DirectX 旧组件和指定 .NET Runtime。

要求：
- 支持仅安装指定类别。
- 支持模拟执行模式。
- 校验安装包存在性和 SHA-256。
- 记录安装开始时间、结束时间、退出码和结果。
- 对重启要求给出提示，不得擅自强制重启。
- 对已满足要求的组件进行合理跳过，避免重复安装。

### Install-Tools.ps1

根据配置清单安装解压工具、浏览器和其他基础软件。

要求：
- 默认只安装明确列出的软件。
- 不捆绑安装广告软件。
- 不修改浏览器首页、默认搜索引擎或系统安全设置。
- 支持单项安装和失败重试。

### Update-Drivers.ps1

只负责检测、下载和整理适用驱动，默认不强制覆盖当前正常驱动。

执行前：
- 获取硬件设备信息。
- 匹配厂商、型号和硬件 ID。
- 验证下载来源和驱动签名。
- 提示可能影响启动的存储驱动及其他高风险操作。

### Start-Setup.ps1

作为统一入口：
1. 检查环境。
2. 检查管理员权限。
3. 识别资源根目录。
4. 展示待执行项目。
5. 要求用户确认。
6. 按安装顺序执行。
7. 保存完整日志和结果报告。

不得默认自动执行系统重置、磁盘格式化、分区删除、引导修复、驱动强制覆盖或系统安全设置修改。

## 七、执行顺序

### 阶段 A：重装前准备

- 确认 Windows ISO 和启动 U 盘可用。
- 备份个人数据、网络配置和重要驱动。
- 将必要网卡驱动及常用运行库存入独立硬盘。
- 检查安装包来源、架构和完整性。

### 阶段 B：系统安装后

1. 检查设备管理器中的未知设备。
2. 如果无法联网，安装对应网卡驱动。
3. 联网后运行 Windows Update。
4. 安装厂商提供的芯片组和必要硬件驱动。
5. 安装 Visual C++ 运行库。
6. 根据需要安装 DirectX 旧组件及 .NET Runtime。
7. 安装常用工具。
8. 生成环境检查报告。

### 阶段 C：验收

必须确认：
- 网络连接正常。
- 设备管理器没有未解决的关键设备异常。
- Windows Update 无待处理的关键更新，或报告未完成原因。
- 常用运行库安装结果正常。
- 系统没有因安装过程被意外重启。
- 所有操作均可从日志中追溯。

## 八、安全及实现原则

1. 所有下载优先使用官方 HTTPS 来源。
2. 不关闭 Windows Defender、UAC 或驱动签名验证。
3. 不使用未经验证的激活工具或第三方系统精简包。
4. 对下载文件执行 SHA-256 校验；校验值必须与可信来源一致。
5. 静默安装参数必须以官方文档为依据。
6. 安装脚本应可重复执行，失败时保留日志并停止依赖该步骤的后续操作。
7. 对有风险的系统修改必须要求用户确认。
8. 默认支持 Windows 11 x64；如实际设备为 Arm64，应切换到对应资源，不得混装架构。
